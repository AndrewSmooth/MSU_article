# Экспериментальный прототип

Минимальный стенд для сравнения случайной и основанной на трассировке стратегий выбора точек отказа. Текущая версия реализует контрольный сценарий и управляемое воспроизведение дефектов `B1`–`B4`.

## Что уже работает

- `order-service` создаёт заказ, вызывает платёж и публикует событие;
- `payment-service` регистрирует платёж;
- `notification-service` получает событие `order.paid` из Kafka;
- PostgreSQL хранит заказы, платежи, попытки, события и уведомления;
- OpenTelemetry Collector передаёт единую трассу в Jaeger;
- контрольный скрипт автоматически проверяет пять инвариантов из [EXPERIMENT_SPEC.md](EXPERIMENT_SPEC.md);
- каждый сервис принимает конфигурацию отказа через одинаковый служебный API;
- поддерживаются задержка, ошибка, недоступность и потеря ответа;
- результаты экспериментов сохраняются в JSONL вместе с идентификатором трассы.
- реализованы случайная и основанная на контрольной трассе стратегии выбора;
- рассчитываются метрики поиска дефектов, воспроизводимости и накладных расходов.

## Запуск

Из PowerShell в этом каталоге:

```powershell
.\start.ps1
```

Первый запуск скачивает Docker-образы и собирает три Python-сервиса. После запуска доступны:

- документация API: <http://localhost:8000/docs>;
- Jaeger: <http://localhost:16686>;
- PostgreSQL: `localhost:5432`;
- Kafka: `localhost:9092`.

## Контрольный эксперимент

```powershell
.\control.ps1
```

Команда создаёт заказ, ждёт обработки события и завершается ошибкой, если нарушен хотя бы один инвариант. Успешный результат содержит:

- один платёж;
- одну попытку оплаты;
- одно опубликованное событие;
- одно уведомление;
- `all_passed: true`.

После запуска в Jaeger нужно выбрать сервис `order-service`. Трасса операции `POST /orders` должна включать также `payment-service` и `notification-service`.

## Эксперименты с известными дефектами

```powershell
.\experiment-b1.ps1
.\experiment-b2.ps1
.\experiment-b3.ps1
.\experiment-b4.ps1
```

Каждый скрипт включает один отказ и проверяет ожидаемый дефект:

| Скрипт | Инъекция | Ожидаемое нарушение |
|---|---|---|
| `experiment-b1.ps1` | потеря успешного ответа после сохранения платежа | `I1_single_payment` |
| `experiment-b2.ps1` | постоянная ошибка платежа `HTTP 400` | `I4_retry_policy` |
| `experiment-b3.ps1` | ошибка публикации после фиксации статуса `PAID` | `I2_paid_order_has_event` |
| `experiment-b4.ps1` | трёхсекундная недоступность платёжного сервиса | `I3_request_within_deadline` |

Каждая запись в `results/experiments.jsonl` содержит конфигурацию отказа, выбранную точку, число активаций, результаты проверки инвариантов, найденные дефекты и `trace_id`.

## Сравнение стратегий

```powershell
.\run-campaigns.ps1 -Campaigns 30 -Budget 8 -BaseSeed 1 -ClearResults
```

Перед серией выполняется контрольный запрос. Скрипт получает его трассу из Jaeger и извлекает значения атрибута `fault.point.id`.

- случайная стратегия выбирает восемь конфигураций без повторений из полного каталога;
- стратегия по трассе использует тот же каталог, но исключает точки, которых нет в контрольной трассе;
- обе стратегии получают одинаковый бюджет и одинаковые случайные зерна;
- порядок стратегий чередуется между сериями.

Каталог содержит 14 конфигураций. В текущем сквозном сценарии выполняются восемь из них. Остальные относятся к чтению заказа, возврату платежа и повторной отправке уведомления.

Результаты сохраняются в файлы:

- `results/campaign_runs.jsonl` — отдельные эксперименты;
- `results/campaigns.jsonl` — итоги серий;
- `results/strategy_metrics.json` и `.csv` — агрегированные метрики;
- `results/trace_points.json` — точки, полученные из контрольной трассы.

## Воспроизводимость

```powershell
.\run-reproducibility.ps1 -Repetitions 10 -BaseSeed 1000 -ClearResults
```

Команда по очереди повторяет конфигурации `B1`–`B4` и считает долю запусков, в которых повторно обнаружен ожидаемый дефект. Результаты записываются в `reproducibility_metrics.json` и `.csv`.

## Накладные расходы

```powershell
.\run-overhead.ps1 -Runs 100 -Warmup 5 -ClearResults
```

Сравниваются два режима одного стенда: обход слоя инъекции и включённый слой без активного отказа. Порядок режимов чередуется. В `overhead_metrics.json` и `.csv` сохраняются среднее, медиана, 95-й процентиль и относительное изменение времени запроса. Распределённая трассировка работает в обоих режимах, поэтому измерение относится именно к слою инъекции.

## Полный сброс

```powershell
.\reset.ps1
```

Команда останавливает стенд и удаляет тома PostgreSQL и Kafka. Следующий вызов `start.ps1` создаёт стенд с чистым состоянием.
